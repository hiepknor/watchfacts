# WatchFacts Runtime + MCP Bridge

Self-hosted WatchFacts Telegram search runtime with MCP tools and OpenWA
handoff support.

The Telegram bot is the primary production runtime and user-facing flow. It
receives WatchFacts queries, runs the deterministic search pipeline, and returns
a compact summary with a generated result page when available.

The `watchfacts-mcp` service is a supporting integration surface. MCP clients
call the same runtime for structured ranked results, pagination, diagnostics,
result-page actions, and optional OpenWA chat draft handoff.

## What It Does

- Runs authenticated WatchFacts searches from Telegram or trusted MCP clients.
- Parses WatchFacts listing data into structured results.
- Matches, scores, and deduplicates listings deterministically.
- Preserves `result_id`, `stable_listing_id`, rank, source, image, seller, and
  pagination metadata for follow-up actions.
- Generates result pages when configured, with Telegram batch fallback.
- Supports operator diagnostics, issue review, and suspicious result QA.
- Optionally uses controlled OpenAI refinement for hard cases; core search does
  not require an LLM.

## Stack

- Python 3.11+
- python-telegram-bot
- HTTPX
- Playwright
- BeautifulSoup4 + lxml
- SQLite
- Docker Compose
- MCP / FastMCP-compatible runtime

## Quick Start

Install local dependencies:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium
```

Create runtime files and configure secrets:

```bash
make init
```

Edit `.env` after `make init`. At minimum, set:

- `TELEGRAM_BOT_TOKEN` for the primary Telegram runtime.
- `WATCHFACTS_URL` when the default WatchFacts URL is not correct.
- Optional OpenWA/OpenAI/result-page values only when those integrations are
  enabled.

Create the authenticated WatchFacts browser state:

```bash
make login
```

Run locally:

```bash
make run
```

Deploy the standard Telegram bot plus MCP runtime:

```bash
make deploy
```

Use scoped deploys when only one service changed:

```bash
make deploy-bot
make deploy-mcp
```

The runtime expects `data/watchfacts_state.json` to exist before real searches.
That file is generated by `make login` and must not be committed.

## Architecture Overview

The runtime is split by responsibility:

- `app/runtime/` owns the Telegram bot, MCP bridge, result-page routes, and
  structured tool payloads.
- `app/searching/` owns WatchFacts parsing, matching, scoring, dedupe, and result
  identity.
- `app/integrations/` owns WatchFacts HTTP/session access, OpenWA handoff, and
  optional AI refinement.
- `app/results/` owns generated result-page storage and rendering.
- `scripts/` contains operator, diagnostic, and fixture-generation utilities.

For module contracts and data model details, see
[Technical Spec](docs/technical-spec.md).

## Runtime Boundaries

- `watchfacts-bot` is the primary user-facing service.
- `watchfacts-mcp` is a trusted integration surface, not a replacement prompt
  implementation of WatchFacts search.
- Matching, parsing, scoring, dedupe, and result identity are runtime logic and
  should remain deterministic unless this project explicitly changes direction.
- MCP clients must preserve returned `result_id`, `stable_listing_id`, rank,
  offset, `next_offset`, source, image, seller, and pagination metadata.
- Clients must not invent seller contacts, prices, product images, source links,
  result IDs, or OpenWA links.
- OpenAI refinement is optional controlled intelligence; it is not required for
  the core WatchFacts search path.

## Security And Compliance

This project must only be used with authorized WatchFacts access and a valid
WatchFacts account.

Do not add code that bypasses login, captcha, Cloudflare, or anti-bot systems.
Do not commit `.env`, Telegram tokens, OpenWA/OpenAI API keys, WatchFacts
credentials, cookies, browser state, SQLite runtime data, logs, or generated
result pages.

Sensitive local runtime files include:

- `.env`
- `data/watchfacts_state.json`
- `data/bot.db`
- `logs/`

For the full boundary, see
[Security And Compliance](docs/security-compliance.md).
